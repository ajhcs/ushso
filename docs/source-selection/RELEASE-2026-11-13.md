# November 13, 2026 technical release

This release promotes the source-selection implementation with accepted-source
publication and optional AI still disabled. It does not complete the source
review, staffing, usability, commercial-pilot or 90-day operating obligations.
Luis Barrigan, Syed Siddiqi and Cole Lyons are the designated source reviewers;
source-specific approvals and weekly capacity remain unrecorded.

The release adds source-publication integrity checks, encrypted and authenticated
browser continuation tokens, and a health build identity that can be matched to
the retained compiled Worker and asset inventory. Previously published legacy
receipts are preserved. The immutable candidate package/lock/CI transition still
says pending review: its technical acceptance is a separate release decision,
not a transfer of historical approval or human source acceptance.

## Qualification and promotion procedure

1. Sol, Terra and Astra independently challenge runtime, source/restore and
   connected release behavior. Resolve concrete findings and retain limitations.
2. Freeze the committed source; run the repository tests, build and Cloudflare
   dry run. Run browser, local Worker and restored-artifact checks sequentially.
3. Retain the exact compiled Worker, all staged assets and their inventory. The
   build identity must have `source_dirty: false`. Upload these bytes using
   `wrangler versions upload --no-bundle`; preserve the existing signing secret.
4. Check the isolated version preview, native invocation of all eight inspection
   tools, and exact static asset bytes. Register the candidate at zero traffic
   and check both production hostnames using the version override header.
5. Promote the verified version, then read back the deployment/version IDs,
   health identity, catalog, default Python clients, browser behavior and assets.

Use `/workspace/build/builderbob/ushso-release/receipts` for the retained evidence.
Record final outcomes separately after they actually occur. Preparation and a
successful upload do not constitute promotion. Receipt timestamps are UTC;
this release date is America/New_York.

## Python client edge access

Default Python urllib requests currently receive HTTP 403 with Cloudflare
`error code: 1010`, before Worker execution. The same request with a different
User-Agent reaches the API. This is consistent with Cloudflare's documented
[Browser Integrity Check behavior](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-1xxx-errors/error-1010/).

`scripts/release-source-selection/configure-api-client-access.py` prepares or
adds one configuration rule, limited to `/api/` on `ushso.org` and
`www.ushso.org`, setting only `bic: false`. It preserves other rules and records
the added rule's deletion endpoint for rollback. It requires a separate scoped
Config Settings Write credential; the existing Worker OAuth login lacks that
permission. Do not describe this issue as fixed until unchanged default Python
requests succeed. Use `check-python-client.py` for bounded status/hash receipts.

`bfed4c53-b186-42d1-bb47-5cf40b7e4657`, deployed at 100% under deployment
`7be18fc5-9c3a-4384-85e2-a8c492c07e8e`. Roll back by deploying that version at

former Plumbob origin; those are not part of this release's mutation scope.
The scoped edge rule is independently reversible using its retained receipt.

The restored-application lane supports the unavailable-publication sentinel.
A full accepted-publication restore remains unsupported: it needs retained
permitted evidence, an independently current rights policy, projection
recomputation, and its own complete application qualification. The synthetic
accepted-ledger rehearsal does not establish that capability. Deploying this
release does not open that disabled path.
