## Code license and artifact reuse are separate

Apache-2.0 describes this repository's declared code license. It does not automatically license third-party dataset payloads, publisher descriptions, documentation, logos, screenshots, archived captures or imported metadata. A source link, public catalog entry or successful HTTP request does not establish redistribution permission. A citation is provenance, not permission.

Complete the following for each published artifact or rights-homogeneous artifact group. Preserve separate decisions for metadata display, quotations, archived captures, API distribution, exports and derived summaries when their permitted uses differ.

| Field | Required record |
|---|---|
| Artifact identity | Source family, release/distribution, capture or file ID; digest; version; publisher |
| Content being reused | Code, source-authored description, factual metadata, quotation, documentation, logo, capture, derived annotation or payload |
| Intended uses | Display, storage, archive, API, downloadable export, adaptation; recipients and scope |
| Permission basis | Exact license/terms or permission correspondence; authoritative locator; evidence ID and observation date; `unresolved` when not established |
| Conditions | Attribution text, notices, modification marking, permitted amount, access restrictions, expiry and any redistribution limits |
| Decision | Reviewer, conflicts/recusal, decision date, allowed/disallowed/unresolved uses and rationale |
| Operational effect | Publish permitted content only; omit/restrict unresolved content as required by the applicable gate; preserve typed reason |
| Withdrawal/change handling | Affected generations, exports and caches; current rights pin; replacement/rollback disposition and retained permitted audit evidence |

An accepted source assertion and its redistribution rights are distinct decisions. A reviewed fact must not become exportable solely because its evidence was accepted. Existing downloads cannot be remotely recalled; record that limitation rather than promising erasure.

The accepted-publication runtime currently requires a separately maintained rights pin and checks bundle identity and expiry. Those checks verify consistency with configured evidence; they do not determine whether the underlying legal interpretation is correct. Do not set a pin from an unreviewed bundle to make the endpoint available.
