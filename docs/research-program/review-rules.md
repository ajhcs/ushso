# Review rules for exact claims

Reviewers inspect one proposed field value at a time. A packet binds:

- record ID and field path
- before/after values
- exact release and context
- cited passage and span
- parser and model versions
- disagreements
- affected products and examples
- hashes of source bytes, proposal, and the packet itself

Identical evidence may be grouped. Separate source identities are never merged by that grouping.

## Dispositions

- accept
- reject
- request evidence
- supersede

Scientific units, denominators, grain, and identity conflicts have higher priority than ordinary source-document interpretation. Owner disclosures use a separate lane.

## Invalidation

Revised source bytes or a changed proposal hash invalidate a prior decision. Stale approvals are not inherited.

## Public facts

Pending proposals are not public facts. A reviewer is never asked to approve an unspecified whole dataset. Every pending essential field has an owner and next step.

Evidence validation is independently replayable from the packet quotation/span against the immutable capture.
