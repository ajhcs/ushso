# Complete the first source review

Start with the [review protocol](review-protocol.md), [exact packet](packet.json), [base ledger](base-ledger.json), [blank records](records.blank.json) and [completion forms](forms.blank.json). Current state is blocked: no human decisions, rights approvals, accepted appointments, study results or production authorization exist. The packet binds eight claims, two source rights reviews, private source bytes and exact paragraph hashes; six other assets are deferred.

Run all commands from the repository root with Node 22.15 or newer. Use a private `/workspace` directory for actual reviews; filenames below are examples, not existing records.

1. Copy packet, base ledger, blank records and completion forms to the private review directory. Complete proposed rights actions, terms evidence, scope and expiry in that private packet. Leave unsupported actions unresolved. Assign and obtain actual role/capacity/contact acceptance. Packet changes invalidate every earlier digest and signature.
2. Run `node scripts/source-selection-approval/review.mjs digest /workspace/private-review/packet.json /workspace/private-review/base-ledger.json`. Transfer the resulting packet and individual digests into actual signed role, claim, rights and independent-challenge records. Reviewers inspect the linked private evidence and publisher terms, document rationale and choose accept/reject/defer/conflict. Do not run the draft preparation script over signed work.
3. Run `node scripts/source-selection-approval/review.mjs preview /workspace/private-review/packet.json /workspace/private-review/base-ledger.json /workspace/private-review/records.json`. Blocked returns exit 2 with missing requirements; malformed or tampered input fails. Bytes and paragraph hashes are checked before preview. Complete actual retrieval, usability/consent, restore and operational records against the protocol; the preview does not generate them.
4. Import actual review outcomes with `node scripts/source-selection-approval/review.mjs import /workspace/private-review/packet.json /workspace/private-review/base-ledger.json /workspace/private-review/records.json /workspace/private-review/ledger null`. For an existing ledger, replace null with its exact revision. Import can retain partial decisions while readiness remains blocked. Original records are preserved. If an accepted rights review allows store_bytes, private paragraph evidence is promoted and copied automatically into the local ledger captures directory with hash/span verification and symlink protection. Otherwise it stays metadata-only, and private review retention remains separate.
5. Build a local generation using the existing `scripts/source-selection/local.mjs rights`, `publish` and `read` commands, binding the returned exact ledger revision and rights hash. This only changes the explicitly selected local ledger. Use a reviewed policy JSON containing `revoked_rights`; never treat an empty list as a new rights grant. Follow the repository release tooling for build and restore qualification. Retained-byte generations require byte-capable restore packaging; the current legacy restore-rehearsal command explicitly rejects unpackaged capture bytes. Record actual checks and human study results in release_reviews; re-run preview. A ready result is ready for generation review, not production authority.
6. Complete the exact_generation form against the immutable artifacts and explicit target. Validate with `node scripts/source-selection-approval/validate-generation.mjs /workspace/private-review/generation-approval.json /workspace/private-review/ledger/ledger-REVISION.json /workspace/private-review/ledger/bundle-HASH.json /workspace/private-review/rights-policy.json EXACT_TARGET`. Replace REVISION, HASH and EXACT_TARGET with observed values. It verifies artifact hashes, generation inputs, projection equality, rights expiry and the actual approval binding. It executes no deployment. Production go-live remains separately authorized and must consume the exact validated artifacts.

AI budget/input/evaluation acceptance is separate; use the AI component's current exact-job authorization contract. The proposed budget or this source-review packet does not enable paid execution. JSON validation establishes structural consistency and digest binding; the operator must verify the private actual-human attestations. Synthetic test records never count as human, rights, paid-call or production evidence.

The enforced production handoff uses `node scripts/source-selection-approval/prepare-release.mjs /workspace/private-review/handoff-inputs.json /workspace/private-review/handoff.json`. The inputs file maps `packet`, `baseLedger`, `records`, `ledger`, `bundle`, `rightsPolicy`, `restoreReceipt`, and `approval` to their actual JSON paths, plus `retainedDirectory`, `currentRightsPolicyPath`, `currentPublicationPath`, `expectedRightsHash`, `currentAssetsDirectory`, `currentWorkerFile`, and exact production `target`. `restoreReceipt` is the actual `restore-smoke.json` produced by the release smoke tool, not a manually constructed pass record. The helper re-verifies the full retained release, external current rights/publication authority, retained capture bytes, actual smoke receipt and current asset/compiled Worker equality. It returns a pinned handoff manifest; it does not deploy. The production wrapper must call `loadAndValidateHandoff` again at dispatch and deploy those verified retained bytes.

Complete operating roles before import; claim/rights records and appointments are immutable imported content. Add `release_reviews` after local generation and restore so their receipts do not create a digest cycle in the accepted ledger. Changing an imported appointment or claim requires a new review/import cycle. The local `publish` and build commands prepare artifacts and do not authorize production.
