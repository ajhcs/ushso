## Atomic commits

### C-024-1 — Reserve worst-case request spend

Compute reservations from input tokens, maximum output/reasoning allowance, selected maximum prices and retry policy. Use atomic durable reservations and a configurable UTC period.

**Verify:** Two workers racing for the final budget unit cannot both proceed; missing price data fails closed.

### C-024-2 — Reconcile actual provider usage

Persist usage/cost/provider IDs on success and uncertain-charge state on interrupted responses. Cap retries and honor Retry-After without repeatedly purchasing the same task.

**Verify:** Tests cover timeout after send, 402, 429, malformed usage and process restart; uncertain charges are not assumed free.

### C-024-3 — Cache by complete task identity

Key cached proposals by source bytes, parser/prompt/schema/model/provider-policy versions and task scope. Emit cost per accepted claim and review workload.

**Verify:** A changed source or prompt invalidates the cache; an unchanged rerun performs no duplicate inference.
