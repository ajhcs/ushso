## Design requirements and ambiguities

**1. Product identity must be canonical, not release-scoped.**
MP:34 and P2:29–31 require source-native product anchors while "Record versions are not extra products," but no normalization key is named. An annual CMS/CDC/Census release that renames or supersedes a dataset can pass as a new product and inflate R04 (MP:34). Requirement: freeze an explicit identity tuple (publisher, program, product, release) where release is a *field of* the product, plus an alias/supersession map for renamed products. Validator: `assert len(products)==100 and len({p.program_key for p in products})==100`; reject any two cohort products sharing `(publisher, program)` under distinct `product_id` unless an alias edge binds them. Failure caught: counting HCRIS 2019 and 2020 as two of the 100.

**2. Dispositions must be keyed on a frozen member population, with reason codes, and enforced by an immutability guard.**
P2:43–44 says unavailable items "stay in the denominator," but C-002-1 seeds 3,434 IDs while the denominator rule in MP:147 exists only as prose. Nothing freezes the eligible set after results are seen. Requirement: `cohorts.json` records all 3,434 baseline IDs with a terminal disposition and reason code; the eligible denominator is the frozen count, never a recomputed "reachable" count. Validator: `assert frozen_count == 3434 and set(manifest.ids) == set(baseline.ids)`; require every disposition ∈ {succeeded, unchanged, failed, restricted, unavailable, unresolved, not_attempted} (MP:147) and forbid `not_attempted` from counting toward the R04 public-sample 80 (MP:33, MP:149). Failure caught: silently shrinking the denominator to 3,380.

**3. Hospital CCN / payer HIOS identity is not MRF reporting binding.**
MP:40 requires locator/disposition per item and P2:41 sources selections from "authoritative directories." AGENTS.md:13 states catalog membership proves no payload access. A CCN or HIOS existing in NPPES/a directory is used to imply a hospital or payer MRF reports. Requirement: each MRF item binds to retrieved evidence of an actual file: reporter legal name, `mrf_url`, `content_type`, `byte_sha256`, retrieval timestamp, and a parser version; the CCN/HIOS is only a *cross-reference*, never the availability proof. Validator: `assert all(m.mrf_url and m.byte_sha256 and m.retrieved_at for m in pilot)`; reject any entry whose only evidence field is a CCN/HIOS. Failure caught: "payer X is in the directory, so its TiC file is covered."

**4. Holdout labels must be a cryptographically separated scorer, not a same-repo hash.**
P2:35 says only "Mark holdout labels inaccessible to implementer tuning." Hashing cohort/tasks (P2:37) does not hide labels if they live in the same frozen artifact an implementer can read. Requirement: holdout task labels/resolutions live outside implementer-readable paths, delivered only to the identical frozen task IDs at scoring time; the committed artifact carries only a commitment hash and empty label fields; implementers' local runs use a disjoint public dev split. Validator: `assert all(t.label is None for t in committed_tasks) and t.split in {"public_dev"}`; recompute `sha256(canonical(holdout_ids))` against the PR-002 commitment and reject any diff. Failure caught: tuning against held-out R14/R07 cases.

**5. Denominators must be frozen as a committed digest and mutation must require an explicit, logged amendment.**
MP:27 and EX:94 forbid lowering thresholds; P2:47 forbids deleting difficult members. But nothing prevents a later PR from editing `cohorts.json`/`tasks.json` in place, invalidating every acceptance row. Requirement: the freeze is a digest over the canonical JSON plus a version; any change is a new version with a before/after report (MP:27), and previous versions remain resolvable. Validator: `assert recompute_sha256(cohorts, tasks) == manifest.frozen_digest`; on mismatch require `manifest.amendment {reason, added, removed, approver}` and reject if `removed` contains any member whose disposition ≠ `not_attempted` for reasons of outcome. Failure caught: post-results denominator edits.

**6. Legitimate amendment must be add-only with per-member provenance; every current member must trace to the original freeze.**
P2:29 seeds all IDs; R04's 100-product cohort is established in PR-002 (MP:54). Ambiguity: can a new intake task add a member after results? Yes only by evidence, not by convenience (MP:54, "deliberately not chosen by whichever records are easiest to enrich"). Requirement: additions require an evidence-backed anchor and a named intake task; no removal of a member can be justified by observed difficulty. Validator: `assert set(current.ids) >= set(frozen.ids)`; for each added member require `anchor.evidence_ref or anchor.intake_task`; flag any `removed` whose `last_status ∈ {failed, unavailable, restricted}`. Failure caught: swapping a hard CMS source for an easy one.

**7. Selection must be blind to endpoint outcomes, and the record must prove it.**
P2:43 says selection is documented before endpoint results are seen. This is stated but not testable, risking a post-hoc narrative. Requirement: the selection commit precedes any retrieval evidence; the handoff carries the selection timestamp/commit and an artifact list containing no fetch receipts at freeze time. Validator: `assert selection_commit_time < min(fetch.received_at for fetch in evidence)` and `assert not any(a.kind=="http_receipt" for a in selection_artifacts)`. Failure caught: choosing only facilities whose files already downloaded.

**8. Cohort size (100/25/10) and the 80/20 sample split must be reconciled against restricted routes.**
MP:33–34 and MP:40 fix 100 products, 25 hospitals, 10 payer entities, with ≥80 public samples; MP:48 says restricted products may satisfy *route* requirements but do not imply payload. Ambiguity: whether restricted cohort members count inside the 100 and how the 80 floor is measured. Requirement: the frozen manifest declares, per member, `access_route ∈ {public_sample, restricted_route, manual_route}` and the R04 report computes `80 = count(public_sample succeeded)` over the frozen denominator only. Validator: `assert report.public_success >= 80 and report.denominator == frozen.size`; reject any report whose denominator equals the succeeded count alone. Failure caught: reporting 80/80 by excluding restricted members.

## Handoff sufficiency

HO lacks fields for the five risks above: no `frozen_digest`, `holdout_commitment`, `cohort_version`, or per-member `identity_tuple`/`mrf_binding`. EX:25–33 defines the handoff, so PR-002 cannot evidence items 1–8 through the current template. I recommend adding those explicit keys before C-002-1 lands.
