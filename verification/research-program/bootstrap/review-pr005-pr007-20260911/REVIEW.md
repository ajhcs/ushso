## PR-005

- **P1 / R005-1 — Keep freshness projections consistent.** `createRetrievalEngine` still calls `freshnessState`, while direct dataset lookup calls the new `projectFreshness`. The numeric browse fallback omits its evaluation clock entirely. The independent `projection-parity` case shows missing evaluation, attempt and payload-scope fields in search and browse responses. Apply one projection contract to all supported routes; do not rely on UI fallback to invent those fields.
- **P1 / R005-2 — Preserve unknown attempt evidence.** `projectFreshness` treats every metadata observation timestamp as a successful check, including supported `unknown` verification states. `catalogAdapter`, `ResultCard` and detail freshness helpers replace explicit null success/attempt timestamps with the old metadata observation date. In the actual rendered card, an undated failed attempt becomes “Sep 3, 2026 (failed).” Preserve explicit nulls and unknown outcomes, and derive success only from evidence that establishes success. Cases: `unknown-observation-not-success`, `explicit-null-attempt`.
- **P1 / R005-3 — Keep unsupported grain out of resolved unit labels.** The adapter and guidance accept every grain state except `unresolved`. Both `inferred` and `unavailable` values render as “Hospital” in the observation-grain slot. Cases with unresolved and supported source-asserted/verified values pass. Require an explicitly supported grain claim; preserve unsupported values as qualified search aids or unknowns. Cases: `grain-inferred`, `grain-unavailable`.
- **P2 / R005-4 — Use a trusted request evaluation clock.** `resolveRequestEvaluationTime` accepts an ordinary caller-supplied HTTP Date header as the freshness clock. The local controlled request changes an overdue September 10 evaluation to a September 4 within-window result. Keep explicit injected clocks for deterministic internal tests, and use server request time for normal requests. Case: `request-date-clock`.
- **Integration blocker / R005-5 — Preserve the complete WP11 boundary.** The independently replayed WP11 attestation suite fails. A complete audit of all 154 historical input pins identifies 11 PR-005 implementation/test/type files changed beyond the two already reviewed package transitions. Updating only ResultCard.test.ts would merely expose the next mismatch. Do not edit historical approvals, receipts, pins or gate policy in the PR-005 correction. A separately bounded current-input attestation correction is required before integration acceptance.

Independent focused freshness/WP1 checks, web tests, retrieval tests and project handoff validation passed. The accepted-base F06/F07 reproductions are retained. The final semantic replay has four passing controls and six failed contract cases. It preserves the original source record and evidence bytes. The initial UI probe lacked Vite build-time environment context; that setup failure and corrected replay are retained. An earlier projection specimen used unsupported `failed`/`none` verification enums; it is not accepted as a product finding. The final case uses supported `unknown` enums.

## PR-007

- **P1 / R007-1 — Preserve qualified identity and release scope.** `publisherToken` replaces punctuation, discards namespace and truncates values. `edition/1` and `edition:1`, different namespaces, and differing long suffixes collapse to the same release ID. The catalog binder also treats a vintage alone as a globally source-scoped release identifier: two different CMS products both become `urn:ushso:release:pub.cms-data-catalog.2023`. Distribution minting trusts a reusable-over-time publisher identifier and returns one ID for two releases with different content. Use collision-resistant full identity material, validated identifier authority/uniqueness, exact source/asset/release scope and documented rules. Preserve literal publisher values. Cases: `release-punctuation`, `release-namespace`, `release-long-suffix`, `distribution-release-scope`, `catalog-vintage-not-global-release`.
- **P1 / R007-2 — Bind every generation and product reference.** An unsupported pin kind bypasses lookup checks. A foreign asset/source release binding attaches to a different record. A valid old publication context plus an explicit current client pin returns old outer publication identifiers with a successful current-generation inner result. Validate publication corpus/version/fingerprint, map, supported pin kinds, record identity and binding ownership together, and return typed restart/unresolved guidance for inconsistent or absent evidence. Cases: `unknown-pin-kind`, `foreign-binding`, `publication-pin-mismatch`.
- **P1 / R007-3 — Require a captured catalog-to-resource relationship.** With no resourcesAPI relationship in the selected catalog entry, the binder accepts an unrelated resources capture and adds `https://example.org/unrelated.csv` as its distribution with no reason code. Require exact qualified linkage; preserve unrelated, missing, mismatched and ambiguous resources as alternatives. Case: `resources-link-required`.
- **P2 / R007-4 — Retain conflicting date values.** `collectDateRoles` keeps the first value as known and replaces the second with null. The second publisher date is lost despite retaining its evidence ID. Preserve both literal alternatives and their pointers; avoid an order-dependent resolved first value. Case: `date-conflict-values`.
- **Required check / R007-5 — Update the current package seal in owned scope.** Independent `npm run validate --prefix packages/identity` fails with `ARTIFACT_MANIFEST_MISMATCH:file_count:expected=25:actual=30`. The controller is authorizing exactly the current identity package manifest and validation receipt as a scope addition, with existing validation and frozen contract dependency pins preserved.

Independent producer regression tests, identity package tests, producer verifier and project handoff validation passed. The independent semantic replay has four passing controls and ten failed contract cases, all executed without probe errors. It uses explicitly synthetic public-shaped metadata; it is not evidence of live source or payload access.

Before acceptance, the correction must also demonstrate reuse of the existing core source/release/distribution and native-identifier contracts, rather than merely copying field names into a parallel schema. The human/machine/dictionary-source map must cite retained actual generation and source-revision evidence.
