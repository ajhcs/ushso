# Source-selection v1

The executable contract is `packages/source-selection/index.mjs`. `projectLedger` accepts an immutable snapshot of assets, captures, rights, decisions, and assertions, validates references and emits non-authoritative `ushso.source-selection.v1` views. Facts are accepted assertions with source locators; proposals are never projected. A verified span is not entailment. Missing and conflicting claims remain typed, and readiness requires independently evidenced critical fields. Identity aliases require accepted, evidenced mappings. Projection consumers must compare generation pins.

`ledger.mjs` provides a local single-host file transaction with exclusive writer lock, content hashes, compare-and-swap and an atomic pointer. It intentionally does not recover locks automatically, register services, deploy, acquire data or authorize paid AI. A changed rights policy makes the retained published bundle unavailable until a corrective generation is published. Callers must maintain the active policy and ensure its blocklist is supplied to projection; this slice does not implement physical deletion or provider caches. Stale locks require manual investigation. This is not a cross-host transaction.

Accepted decisions bind exact existing assertion IDs, evidence, reviewer identity and subject; accepted records are immutable across committed snapshots. Scoped conflicting assertions are not combined. Finite validity on a critical assertion conservatively prevents readiness until dated-scope evaluation is implemented. Byte-retaining captures not revoked by the active rights policy are read from the local ledger captures directory and checked against their SHA-256; revoked bytes may be removed while permitted historical metadata remains; assertion byte ranges and quote hashes are checked against those bytes. This does not establish semantic entailment or validate an extracted-text-to-page mapping. Projection is deterministic with respect to its inputs; expiry is enforced at serving time. An explicit recover-lock command requires the observed lock hash, a matching host and boot ID, and a dead PID. It checks the accepted ledger, records an immutable receipt, and retains staging files. The storage check compares the target filesystem device with /workspace and requires 16 MiB available via statfs. SIGKILL has been exercised before and after the accepted pointer switch; other crash boundaries remain unqualified.

Manual refresh reporting: `node scripts/source-selection/refresh-report.mjs LEDGER.json PLANS.json ATTEMPTS.json POLICY.json AS_OF_UTC`. Plans is an array of `{asset_id, rights_id, owner, due_at, review_due_at}` using UTC timestamps; attempts is an array of `{attempt_id, asset_id, owner, attempted_at, outcome, capture_id?, retry_after_at?}`. Successful `changed`/`unchanged` attempts require an existing same-asset capture; failures cannot replace it. `retry_after_at` is a recorded earliest retry, not a request or an inferred publisher limit. The report is read-only, returns unplanned assets, and explicitly leaves reviewer capacity unknown. Plan dates and attempts require operator evidence; this command does not create them or run a scheduler.

The local `scripts/source-selection/restore-rehearsal.mjs` prototype verifies a separately hash-pinned `ushso.restore-package.v1` JSON package and independently supplied current policy and compatibility data before materializing six role artifacts into a fresh workspace directory. It refuses changed rights, invalid pins and supported byte captures without packaged artifacts; it never switches an active pointer. Its filesystem tests use synthetic application bytes. The format loads base64 package contents into memory, has no unavailable-publication mode, and does not package or run the actual application, validate secrets or demonstrate a health check. It is not a full release restore or an M13C receipt. A complete rehearsal needs a streamed immutable directory inventory for the actual large build, independently pinned current rights, executable Worker/config/runtime compatibility, and isolated health and source checks.

Each published view carries one `citations` entry per `evidence_ids` capture: canonical publisher URL, retrieval timestamp, optional captured-content SHA-256, locator scheme, and the accepted assertion locators. Metadata-only captures carry a null content hash. Only rights-permitted accepted evidence is projected; raw excerpts and capture bytes are not included. Missing or malformed citation metadata invalidates the view rather than manufacturing a citation.

`rights.actions.publish_metadata` is a distinct reviewed permission covering publication of projected metadata and citation fields through public HTML and APIs and inclusion in user exports. It does not authorize source bytes, raw excerpts, or payloads; `redistribute_excerpt` remains separate. Missing, unresolved, or prohibited `publish_metadata` prevents evidence-derived claims and citations from entering the public projection even if metadata capture is allowed. This field does not infer or grant a publisher's terms.

A public view also requires a current accepted identity assertion, backed by permitted evidence, that matches the asset ID, publisher ID, and title. Assets without that evidence remain in the internal inventory and do not appear in accepted public views; revocation can therefore leave a rights-valid empty generation.
